# VIO experiment view (fork)
- Two visible software-driver cards; the six-slot CU frame is unchanged. New configuration defaults to two enabled drivers. Existing configs can disable additional slots under Session > Additional slots (an enabled hidden slot can still affect race results).
- System > RPi Connection uses SSH with host-key verification. Trust the Pi key with your normal SSH client first. Password is not persisted. Key authentication is supported.
- VIO has independent Run/Stop for the remote sender and existing local receiver. The saved remote directory and command (including laptop IP) are reused; numeric Pi parameters are appended as CLI options and saved for the next run. The numeric fields override duplicate options in the base command. Select the local Python file, optional arguments and interpreter. The receiver uses its own working directory and reports the actual dataset path. Dataset selection is restored from the saved receiver path on opening VIO; renamed recordings are located using summary.json. Do not use receiver --carrera-device concurrently with RaceLab.
- Keep GStreamer installed as required by the receiver. Update laptop_receiver.py in vio-gstreamer-pi-zero-w2 to commit 5d0b854 or later. RaceLab supplies --preview-port automatically, using GStreamer multipartmux and tcpserversink on localhost; native preview remains the default for standalone receiver use. FFmpeg (with libx264) is needed only for Replay, which transcodes completed MKV into a temporary browser-compatible MP4. The recording branch is unchanged.
- Local process/SSH endpoints are deliberately restricted to localhost; existing API authentication also applies. Remote/local capture stop is graceful; if the process doesn't exit, inspect logs before manual intervention.
- Initial hardware validation: run receiver first, then sender; check preview, IMU files, stop sender, then receiver, check dataset, replay. Existing CU E-stop is unchanged.
